# Tunnels and cryptography checks

Severity scale: CRITICAL / HIGH / MEDIUM / LOW. Every command is read-only. Method and output format: `routeros-audit-method`.

## 1. Cryptography, certificates and tunnels

| Check | Read command | Characterises a failure | Sev. |
|---|---|---|---|
| PPTP enabled | `/interface pptp-server server print` + the input filter for tcp/1723 | `enabled=yes` reachable from an untrusted network — MS-CHAPv2 broken for years, no fix possible. Enabled but filtered to a closed segment: HIGH | CRITICAL |
| L2TP without IPsec | `/interface l2tp-server server print proplist=enabled,use-ipsec,authentication,default-profile,one-session-per-host,max-sessions` + `:put [:len [/interface l2tp-server server get ipsec-secret]]` | `use-ipsec` other than `required` (`yes` is opportunistic and still accepts clients without IPsec), or secret length `0`. The PSK value is never printed | CRITICAL |
| Cleartext PPP authentication | `/interface <type>-server server print proplist=enabled,authentication` and `/ppp aaa print` | `authentication` accepting `pap`, or `mschap1` without need, on a tunnel whose transport is not protected (PAP inside `use-ipsec=required` is protected) | HIGH |
| PPP session without cipher | `/ppp active print count-only` first, then a narrow `where` (never a full listing on a concentrator with thousands of sessions) | **empty** encoding on a PPTP/L2TP/SSTP session that should be encrypted. Empty encoding on PPPoE is normal | HIGH |
| PPP profile not requiring cipher | `/ppp profile print proplist=name,use-encryption,only-one,local-address,remote-address,disabled` | on profiles used by tunnels across an untrusted network: effective `use-encryption` other than `required` (`default` inherits — resolve it). Not applicable to PPPoE access | HIGH |
| Multiple sessions per subscriber | `/interface pppoe-server server print proplist=interface,service-name,one-session-per-host,accept-empty-service,authentication,disabled` | `one-session-per-host=no`: one credential opens N sessions, drains the pool and the CPU. A capacity policy — confirm with the operation | MEDIUM |
| Concentrator accepting empty service | same command | `accept-empty-service=yes` — a client that does not state the service name gets in | MEDIUM |
| Concentrator with an IP on the access interface | `/ip address print` crossed with `/interface pppoe-server server print` | the interface where PPPoE listens **must not have an IP address** | MEDIUM |
| PPPoE client without a fixed AC | `/interface pppoe-client print proplist=name,interface,user,service-name,ac-name,use-peer-dns,add-default-route,default-route-distance,disabled,running` | `ac-name` and `service-name` empty: connects to **the first concentrator that answers** — open door for a rogue concentrator on a shared segment | MEDIUM |
| Route and DNS dictated by the link | `/interface pppoe-client print proplist=name,interface,user,service-name,ac-name,use-peer-dns,add-default-route,default-route-distance,disabled,running` | `use-peer-dns=yes` and `add-default-route=yes` on an unapproved link | MEDIUM |
| Remote access created by the wizard | `/interface l2tp-server server print proplist=enabled,use-ipsec,authentication,default-profile` + `/ppp secret print proplist=name,profile,service` + named `/ip cloud get` fields only (settings menu: no `proplist`; no secret-bearing field) | VPN raised by Quick Set: generic user, and the wizard itself leaves **`Firewall Router` unchecked** | CRITICAL |
| Home tunnel with the admin credential | `:put [/ip cloud get back-to-home-vpn]`, `/interface wireguard peers print proplist=interface,public-key,allowed-address,endpoint-address,endpoint-port,disabled`, `/user print proplist=name,group` | Back To Home active: the app asks for **the administrative credential** to build the tunnel, and offers file access in full mode. Unknown peer in the list = remote access nobody registered | HIGH |
| Tunnel credential handling | inspect only non-secret metadata with explicit `proplist` fields | assess whether the tunnel uses an approved authentication mechanism and protected transport. Secret strength is intentionally not assessed; never retrieve PSKs/passwords | MEDIUM |
| Weak SSTP | `/interface sstp-server server print proplist=enabled,certificate,force-aes,tls-version,authentication,default-profile` (`tls-version` exists on v7 only) | `certificate=none`, `force-aes=no`, or `tls-version=any` (accepts TLS 1.0) | HIGH |
| Weak OVPN | `/interface ovpn-server server print proplist=enabled,auth,cipher,require-client-certificate,certificate,protocol,port,default-profile` (`protocol` exists on v7 only) | `auth=none`/`md5`/`sha1`, `cipher=null`/`blowfish128`, or `require-client-certificate=no` | HIGH |
| IPsec with weak algorithm | `/ip ipsec proposal print proplist=name,auth-algorithms,enc-algorithms,pfs-group,disabled` and `/ip ipsec profile print proplist=name,hash-algorithm,enc-algorithm,dh-group,nat-traversal,dpd-interval,dpd-maximum-failures` (the profile has no `disabled`) | `auth-algorithms=md5`/`sha1`, `enc-algorithms=des`/`3des`, `dh-group` below `modp2048` | HIGH |
| IKEv1 aggressive with PSK authentication | `/ip ipsec peer print proplist=name,exchange-mode,profile,disabled` + `/ip ipsec identity print proplist=peer,auth-method,disabled` | `exchange-mode=aggressive` combined with `auth-method=pre-shared-key`; no PSK value is required or permitted in collection | HIGH |
| IPsec PFS policy | `/ip ipsec proposal print proplist=name,auth-algorithms,enc-algorithms,pfs-group,disabled` | inspect `pfs-group` in the Phase 2 proposal. `none` may be intentional for interoperability (including documented IKEv2 client cases); flag it only when the security policy explicitly requires PFS | MEDIUM |
| WireGuard with a broad peer | `/interface wireguard print proplist=name,listen-port,public-key,mtu,disabled` and `/interface wireguard peers print proplist=interface,public-key,allowed-address,endpoint-address,endpoint-port,disabled` (v7 only) | `allowed-address=0.0.0.0/0` outside a full-tunnel scenario; `listen-port` exposed without an input filter | HIGH |
| WireGuard preshared-key presence | `/interface wireguard peers print count-only where preshared-key=""` | count above zero: peers without a preshared key where margin against future cryptanalysis is required. The filter tests presence; the key is never printed | LOW |
| VXLAN without cipher | `/interface vxlan print proplist=name,vni,port,local-address,disabled`, `/interface vxlan vteps print` and `/interface vxlan fdb print` | VXLAN crossing an untrusted underlay without IPsec/WireGuard underneath (customer L2 in cleartext), VTEP/VNI outside the inventory, or udp/4789 reachable from any source | HIGH |
| ZeroTier | `/zerotier print proplist=name,port,disabled` + `/zerotier interface print proplist=name,network,allow-default,allow-global,allow-managed,disabled` + `/zerotier peer print proplist=interface,address,role,latency,path` (v7 only, `zerotier` package) | network ID nobody recognises, `allow-default=yes` (the device's default route starts leaving through the overlay), `allow-global=yes`, or interface bridged with the LAN without segmentation | HIGH |
| EoIP protection | `/interface eoip print proplist=name,remote-address,tunnel-id,disabled` + `/interface eoip print count-only where ipsec-secret=""` | tunnel over the Internet with no `ipsec-secret` (count above zero) and no other protected transport under it: an L2 bridge open to whoever forges the endpoint. The secret is never printed | HIGH |
| Badly built port knocking | `/ip firewall filter print detail` and `/ip firewall address-list print` | knock sequence without `address-list-timeout`, or the final port drop missing — the knock protects nothing | MEDIUM |
| Certificate | `/certificate print proplist=name,common-name,subject-alt-name,issuer,serial-number,fingerprint,invalid-before,invalid-after,expired,revoked,trusted,private-key,key-type,key-size,signature-algorithm` | detailed in `routeros-audit-certificates` | HIGH |
